# 完整运行案例

[English](EXAMPLES.md) | **简体中文** · [README](../README.zh-CN.md)

在仓库根目录执行 `python3 examples/run_demo.py`。实际 JSON 结果写入 `results/demo/`；用 `--output results/another-run` 可选择其他输出目录。案例使用完整枚举与随附工具，不需要外部求解器。

## 1. 求解成功，但订单要求遗漏

两种产品 A、B 的整数产量为 x、y：

\[
\max\ 80x+50y,\quad 3x+2y\le40,\quad2x+y\le25,\quad
0\le x\le12,\quad0\le y\le20.
\]

业务订单另有 `y>=6`。只有资源约束的模型给出 `(10,5)`、利润 1050，却违反订单。需求清单可以指出已登记要求没有模型映射，独立订单验证器会拒绝 y=5。加入 `[0,-1]*[x,y]<=-6` 后，名义最优为 `(8,8)`、利润 1040。

每个模型完整检查 13*21=273 个候选，并将原资源/数量规则的独立计算与矩阵回验对照。这里的最优性证据来自小型有界域的完整枚举。登记记录一致本身不能证明代码正确实现业务语义。

## 2. 固定方案需要多少缓冲？

声明机器容量变化界为 2 小时、材料容量变化界为 1 单位，系数、订单和变量界固定。在同时最坏变化下保持可行，等价于本例容量收紧到 38 和 24。最优为 `(8,7)`、利润 990，消耗机器 38、材料 23。

机器的名义余量为 2，单位半径的最坏变化为 2，因此最大半径为 1；材料余量为 2、变化为 1，半径为 2，整体取最小值 1。原名义最优 `(8,8)` 用满 40 小时机器，对声明机器变化的半径为 0。

利润牺牲 50，约为正确名义利润的 4.81%。换取的是声明集合内可行性，不保证实现利润更高；相关变化可能使独立盒过于保守，也没有未知分布概率保证。

如果订单变成 y>=8，旧矩阵仍能让 `(8,7)` 通过。语境版本变化返回 review_required，重建新约束后候选被拒绝。版本与时间由调用者提供，不是自动系统同步或在线监控。

## 3. 决策前的含噪检测是否值得付费？

这是独立的合成工艺选择问题。两种行动在两种状态下都可行，损失单位为元：

| 行动 | 正常材料（概率 .5） | 困难材料（概率 .5） | 期望损失 |
| --- | ---: | ---: | ---: |
| 普通工艺 | 0 | 100 | 50 |
| 谨慎工艺 | 40 | 40 | 40 |

不测量时选择谨慎工艺，损失 40。理想完全信息下，正常材料选普通工艺、困难材料选谨慎工艺，损失 20，因此 EVPI=20。

决策前含噪检测的似然矩阵为 `[[.8,.2],[.2,.8]]`，行为材料状态，列为正常/困难信号。两种信号概率均为 .5。收到正常信号时，普通工艺的后验期望损失为 20，优于谨慎工艺；收到困难信号时，选损失 40 的谨慎工艺。整体损失 .5*20+.5*40=30，因此 EVSI=10。

含噪检测成本为 5，净价值 5；完美检测若收费 25，净价值为 -5。给定有限表与风险中性条件下，工具选择含噪检测。概率和测量准确率都是假设，并非真实校准或必然回本证据。

## 输出文件

| 所选输出目录内的文件 | 内容 |
| --- | --- |
| production-comparison.json | 枚举最优、候选数、缓冲成本、重复约束及单位变换检查 |
| order-test-evidence.json | 实际执行的订单拒绝与边界测试 |
| contract-input.json / contract-reports.json | 需求映射、缺失及修正后的审查结果 |
| plan-input.json / plan-reports.json | 名义/缓冲包络、语境变更和新订单回验 |
| information-input.json / information-report.json | 假设损失/观测表及计算的信息价值 |

用于真实问题时替换输入，保留真实单位、规则、决策时序、快照和证据。大模型需要适配求解器，扩大暴力枚举不是规模化方案。测试验证软件和合成不变量，未验证独立智能体行为或现场工业效果。
