# 不确定性、服务与场景评估

[English](../uncertainty-and-scenarios.md) | **简体中文**

在需求、时间、成本、供给等不确定量影响决策，或任务主张样本外收益时读取。无此需求时不默认加入复杂随机模型。

## 先确定不确定性来自哪里

区分：可估计随机波动、参数估计误差、结构失配、极端压力情形与未知概率。保留时间/空间/实体之间的依赖；独立抽样可能制造不合理组合。

记录预测/场景/不确定集的来源、训练截止点、量纲和校准方式。数据不支持分布假设时，以区间与明确情景分析回答条件性问题；不能把“等权”或专家设置的概率称为实测分布。

## 选择与问题匹配的建模路线

| 路线 | 何时考虑 | 必须解释的边界 |
| --- | --- | --- |
| 名义确定模型 | 误差影响小或作为基线 | 不保证随机波动下可行 |
| 情景期望/两阶段模型 | 有可用情景/权重，能表达补救 | 先决策、后观测，补救有限且计费 |
| 机会约束 | 用户明确容许概率性服务违约 | 联合/逐条概率区别、概率校准与样本保证条件 |
| 鲁棒模型 | 需在明确不确定集内保持要求 | 保证相对集合成立；集合外未知，保守性有代价 |
| 分布鲁棒模型 | 分布不确定且有可校准歧义集 | 集合、半径/参数来源与适用保证；不是自动更可靠 |
| 风险目标/约束 | 关注高损失而非只看均值 | 统一损失口径、水平参数、权重与服务解释 |

禁止观察未来场景后重新选择提前决策并将其当作可执行策略。多阶段情景树需要非预见性；补救决策只能使用其时点可见的信息。完美信息 oracle 可以用于界或诊断，标注不可直接实现。

## 统一指标

在同一评估场景与相同费用/补救规则下报告适用的期望成本、服务短缺、硬约束违反和尾部风险。短缺罚费不意味着用户授权违反硬约束。

服务指标区分：无短缺概率、需求量加权满足率、最大短缺、按组/时段的服务。平均比例与总量比例不是同一指标。总体较好不自动代表每个组都满足要求。

成本损失 ℓ 的离散情景 CVaR 可用：

\[
\operatorname{CVaR}_{\alpha}(\ell)=\min_{\eta}\left[\eta+\frac{1}{1-\alpha}\sum_s p_s(\ell_s-\eta)_+\right],\quad0\le\alpha<1.
\]

情景权重非负且总和为 1。CVaR 衡量上尾成本，不是置信区间；对离散分布需要按概率质量分割边界情景，不能简单平均“超过 VaR 的几个样本”。若成本来自代理仿真，CVaR 同样是该代理与分布下的指标。

优化 E[ℓ]+λ CVaR 时，α、λ、量纲与偏好来源明确；这会改变目标，不自动等价于服务保证。训练/评估中有限情景的 CVaR 不认证总体尾部风险。

## 评估与压力测试

按决策时间分离拟合/训练、调参和评估数据。冻结策略后评估；任何基于测试表现修改策略的步骤都使它成为新一轮调参，需新的独立评估。

真实历史回放可能缺少未采用动作的结果；有反事实或策略选择偏差时说明识别限制。仿真或情景成本比较是模型条件下的证据，不直接证明实际因果收益。

压力测试单列需求峰值、供给延迟、故障或参数偏移，并说明其设计依据。没有概率校准的极端情景不混入期望成本，也不能把“通过测试列表”称为全域鲁棒认证。

随机评估报告样本数量、独立单元和配对方式；稀有事件没有观测到，不说明其真实概率为零。人工情景权重不是 IID 样本，不能直接按情景个数计算置信区间。

## 场景评估器

`scripts/evaluate_scenarios.py` 仅依赖 Python 3 标准库。它读取共享情景下已经计算/观察的方案结果，输出权重期望、CVaR、服务及硬约束违反概率。它不求解、不模拟、不拟合概率、不认证总体可靠性。

输入约定：

```json
{
  "distribution_kind": "hypothetical",
  "cost_unit": "yuan",
  "demand_unit": "units",
  "alpha": 0.9,
  "scenarios": [
    {"id": "low", "probability": 0.25, "demand": 4},
    {"id": "mid", "probability": 0.5, "demand": 8},
    {"id": "high", "probability": 0.25, "demand": 14}
  ],
  "policies": [
    {"id": "stock-8", "outcomes": [
      {"scenario_id": "low", "status": "ok", "total_cost": 20, "shortfall": 0, "hard_violation": false},
      {"scenario_id": "mid", "status": "ok", "total_cost": 16, "shortfall": 0, "hard_violation": false},
      {"scenario_id": "high", "status": "ok", "total_cost": 46, "shortfall": 6, "hard_violation": false}
    ]}
  ]
}
```

`distribution_kind` 必须声明为 `hypothetical`、`empirical` 或 `calibrated`；名称是输入声明，脚本不会核实真实性。每个方案必须具有同一组情景且恰有一条记录；概率严格非负且总和在 1e-9 内等于 1，仅校正浮点总和误差。不能默认删除缺失或失败情景。

`shortfall` 在 [0,demand] 内，和 demand 采用同一单位；`hard_violation` 必须显式布尔值。某情景执行失败时使用 `status: failed` 和非空 `error`，不用伪造成本/服务字段；该方案完整期望、服务和风险指标标为未知，同时报告失败概率和数量。零概率情景可以保留用于追溯；其失败同样使完整评估不通过。

`alpha` 默认 0.9，必须在 [0,1)；`shortfall_tolerance` 默认 0，是对服务短缺发生的报告阈值，不修改短缺数量或硬约束规则。成本允许为负，但必须统一为“越小越好”的总损失口径。

调用：`python3 /实际技能路径/scripts/evaluate_scenarios.py /实际输入路径/scenarios.json`。

退出码 0 为全部情景评估完整，1 为存在执行失败而部分指标未知，2 为输入错误。完整不等于所有硬约束满足：输出会显式报告违反概率，使用者必须检查它。工具报告的是输入分布下的指标，不生成置信区间、显著性或真实场景概率声明。

可直接使用 [合成补货评估输入](../../assets/scenario-example.json) 运行工具。该教学例取 q∈{0,…,15}，成本为 ℓ(q,d)=2q+(q-d)₊+5(d-q)₊。建模需求情景为 {4,8,14}，权重 {0.25,0.5,0.25}：最小期望成本选择 q=8；最小 E[ℓ]+CVaR₀.₉(ℓ) 选择 q=12；要求覆盖这些建模情景并最小化期望成本选择 q=14。三种策略冻结后，在需求 {6,10,16}、同一组人工权重下比较，输入已给出各情景成本、短缺和物理容量检查。短缺属于服务指标，硬约束标记仅对应 q 的物理域。它只示范输入与计算，不代表真实需求预测或总体保证。
