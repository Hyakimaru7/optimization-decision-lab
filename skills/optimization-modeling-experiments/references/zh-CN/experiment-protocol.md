# 优化建模实验协议

[English](../experiment-protocol.md) | **简体中文**

## 实验问题与预算

每个实验对应明确问题，例如：两种建模方式在相同服务要求下的成本差异；松弛误差随规模如何变化；鲁棒模型的样本外违约率是否下降；求解效率对稀疏性是否敏感。

事先记录主指标、基线、变化因素、实例来源、抽样单位、调参范围、停止条件、精度和资源预算。探索中增加实验可以，但注明它是看到结果后的追加实验。

默认起步配置可采用配置模板：一个可核查的小实例、单次冒烟求解、每次 60 秒上限、固定数据种子。其目的是验证流程，不足以支持稳定性能优势。无明确批量预算时先完成起步配置并用实测时间估算规模；预算明确时继续完成约定实验。

常用起步容差 1e-6 只作为初始建议；应结合物理单位、问题尺度、研究要求和求解器能力调整，记录有效配置及后端参数映射。

## 数据与实例

真实数据记录来源、访问/许可条件、版本、读取时间、校验哈希、缺失和过滤规则。合成数据记录分布、参数、生成器版本和种子；不要以合成性能代表真实应用性能。

使用共享问题实例比较不同方法。随机场景、预测器或不确定集的训练与测试分离；采用时序数据时避免未来信息泄漏。

区分三种随机性：问题实例生成、算法自身随机性、执行环境计时波动。分别记录种子/重复层级。固定种子不足以保证逐位复现，还需要记录后端、版本、线程及硬件。

## 比较口径

- 比较求解器时，使用同一原模型及可比较的质量目标；相同名义容差不一定等于相同原模型残差。
- 比较不同模型时，保存各自目标与共同应用指标，明确可行域、目标尺度和服务水平差异。
- 比较松弛与整数模型时，说明界、恢复策略和原整数可行性，不直接把松弛目标称为更优可行方案。
- 各方法采用可比调参预算；调参数据与最终评估实例分开。披露默认参数与专门调参结果。
- 显式说明线程数、时间上限、热启动、预处理、编译和模型构建计时。冷启动/热启动分别评估，不混在同一汇总中。
- 时间至少分解为建模/转换、求解、回验及端到端时间；求解器内部 solve_time 不替代总时间。
- 需要时记录内存测量方式、迭代数、节点数和 oracle/通信成本。不同计数含义不能直接合并。

## 最小验证实例

至少检查一个具有解析解、可枚举解或可信交叉结果的小实例，及与模型有关的失败/边界实例。通过不意味着所有实例正确，但应覆盖会改变结论的关键语义。

对光滑实现可用有限差分或方向导数核查导数；在非光滑点不用普通梯度误差判定失败。梯度步长需兼顾截断与浮点误差。

有参考求解器时交叉检查；两求解器一致仍不是精确数学证明。失败测试包括不可行、无界、零容量、整数恢复、未闭合 gap 或缺失解，按任务选择。

## 实验组合

| 类型 | 目的 | 注意事项 |
| --- | --- | --- |
| 主比较 | 回答研究假设 | 共享实例，先定义质量标准 |
| 消融 | 识别某个机制的贡献 | 保持其他条件，说明变化是否改变可行域 |
| 敏感性 | 检查参数稳定性 | 参数范围有依据；单因素未覆盖交互 |
| 规模实验 | 检查时间/内存增长 | 记录稀疏度、结构及 timeout，不只报告成功点 |
| 样本外评估 | 检查泛化与稳健性 | 独立场景、相同执行/补救策略 |

参数变化导致最优解不连续或多解时，区分目标稳定与决策稳定。不存在唯一最优解时不同解向量不必意味着实现错误。

## 原始记录约定

建议 JSONL：一行一个运行/尝试。每次尝试有唯一 `run_id`，并能映射到预定实验单元。最低包含：

| 字段 | 含义 |
| --- | --- |
| experiment_id, run_id, attempt, instance_id | 实验、尝试及实例身份 |
| model_id, method, solver, solver_version | 建模与后端身份 |
| data_hash, code_revision, config_path | 数据、代码及配置的可追溯信息 |
| instance_seed, algorithm_seed, repeat | 随机性层级；不适用时 null |
| n_variables, n_constraints, n_nonzeros | 定义明确的规模统计 |
| status_raw, termination_reason, has_solution | 原始终止信息 |
| objective_original, objective_solver | 原目标与后端目标及其映射 |
| lower_bound_original, upper_bound_original, bound_source | 界及证据；未知为 null |
| gap_abs, gap_rel, solver_gap | 不混合自定义与后端 gap |
| feasibility_by_class, integer_violation | 残差、单位、尺度和容差判定 |
| optimality_measure, validation_outcome | 使用的证据与回验结果 |
| build_seconds, solve_wall_seconds, verify_seconds, total_seconds | 计时边界明确的时间 |
| solution_path, log_path, error | 解、日志及失败原因 |

只生成对任务有用的字段，但不得省略身份、状态、解是否存在、回验和计时口径。JSON 不写 NaN/Infinity，缺失值为 null，错误消息保留原因。

维护计划清单，汇总报告分母来自计划单元而非只来自成功记录。重试保留全部尝试，汇总策略预先规定，不挑选最快或最好尝试作为默认结果。

## 汇总与图表

按状态统计：满足质量标准、仅可行、低精度、限时、正常不可行/无界、技术错误及未执行。准确说明指标的有效样本数。

随机实例上进行配对比较；报告差值分布或置信区间时说明重采样单位和独立性。确定性求解的重复计时不能扩大问题实例样本数。统计检验只在任务需要且假设适用时使用，比较多项指标时说明多重比较处理。

时间上限产生删失数据，不能当作真实收敛时间；可以报告限时未达标数或预先定义的惩罚指标，并说明公式。不能直接删去超时后宣称整体更快。

图表注明单位、尺度、误差带、有效样本数及时间上限。对数轴不静默丢弃零/负值；不从短区间曲线外观推断理论率。

## 复现交付

保存运行环境：操作系统、CPU/GPU、内存、线程、Python/其他语言版本、实际依赖和求解器版本。保存可恢复的代码状态；已有 Git 仓库可记录提交与差异，否则使用文件哈希。

至少给出数据准备、单实例、批量、回验和汇总的实际入口（可由同一脚本的不同参数实现）。输出不要覆盖原数据；恢复批量实验按运行身份跳过已完成单元，并保存状态与配置冲突处理。

交付报告使用 [报告模板](../../assets/zh-CN/research-report-template.md)，删去无关章节。证据不足的主张明确降级；不能把尚未执行的方案写成实验结果。
