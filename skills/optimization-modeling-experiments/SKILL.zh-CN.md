# 优化建模与实验验证

[English](SKILL.md) | **简体中文**

把用户的问题转化为语义清楚、数学一致、可执行且可核查的优化决策，并以实验检验模型与方案。分别检查问题表述、模型求解和应用效果；仅在正确建模、方法适用性或结果解释需要时展开理论推导。

## 任务范围与默认行为

适用于 LP、QP、凸锥优化、连续非线性优化、MILP、MIQP、约束规划及需要特别处理的非凸模型。随机、鲁棒、双层、动态、多目标与昂贵黑箱问题按其结构处理，不套用普通凸优化保证。

识别当前请求：需求澄清、建模、审查、实现求解、方案/方法比较、复现、科研探索或运行中的规划。简单问题优先最小充分模型；不默认引入风险、仿真或统计模块。完整实验请求不止于给出计划。

优先沿用项目语言、依赖、符号和目录。无既有工具链时，优先考虑 Python 与适合模型结构的开放工具；检查已安装的建模库、实际求解器及许可。技能本身不要求联网、商业许可或固定求解器。

只询问会实质改变模型含义或阻止执行的缺失信息，如目标方向、变量是否整数、硬约束是否允许违反。可独立推进的部分继续执行。其余缺项用标注的临时假设，并解释其影响；合成数据显式标为合成数据。

## 按需读取

- 从自然语言、业务表格或生活目标建模，或需要选择实际方案时，读取 [问题与决策](references/zh-CN/problem-to-decision.md)。
- 建模、重构、量纲或约束语义有疑问时，读取 [模型审查](references/zh-CN/model-audit.md)。
- 选求解器、核查解、解释状态或最优性时，读取 [求解与认证](references/zh-CN/solver-validation.md)。执行数值求解时必须使用其中的原模型回验流程。
- 比较、复现、敏感性或批量实验时，读取 [实验协议](references/zh-CN/experiment-protocol.md)。
- 存在预测误差、未知分布、供给波动或样本外主张时，读取 [不确定性与场景](references/zh-CN/uncertainty-and-scenarios.md)。
- 需要落地计划、时间递推、仿真回放、重规划或执行反馈时，读取 [操作验证与滚动规划](references/zh-CN/operational-validation.md)。
- 探索选题、模型失配、参数辨识、实验设计或昂贵黑箱问题时，读取 [科研探索](references/zh-CN/research-exploration.md)。
- 需求较多、多人交接、模型反复修改或关键约束可能遗漏时，读取 [需求契约与反例](references/zh-CN/requirement-contract.md)，按需使用 [契约审查器](scripts/audit_requirement_contract.py)。它核查已登记的映射与证据记录，不证明自然语言与公式等价。
- 准备复用旧计划、判断资源缓冲或数据变化后是否需重新核查时，读取 [方案有效范围](references/zh-CN/plan-validity.md)，线性固定方案可用 [有效范围检查器](scripts/assess_plan_validity.py)。模型/数据/业务版本变化须重新核查，工具不自动放行运营操作。
- 在“先测量/试验还是直接决策”之间选择时，读取 [决策信息价值](references/zh-CN/decision-information.md)，完整离散损失表可用 [信息价值评估器](scripts/evaluate_information.py)。不凭空生成概率、测量精度或实验收益。
- 用户要求检验本技能或工作流程时，读取 [验收案例](references/zh-CN/acceptance-cases.md)。不用默认运行所有案例。
- 新建完整实验时，可复制 [配置模板](assets/experiment-config.json) 和 [报告模板](assets/zh-CN/research-report-template.md)，按当前任务删减。模板是约定，不是任何求解器的直接输入。
- 需要独立回验 LP/MILP 候选解时，可使用 [线性解检查器](scripts/check_linear_solution.py)；输入格式与限制见 [求解与认证](references/zh-CN/solver-validation.md#线性解检查器)。它只核查候选可行性和目标，不求解或认证最优性。
- 比较相同场景下的方案成本、服务短缺和尾部风险时，可使用 [场景评估器](scripts/evaluate_scenarios.py)，格式及限制见 [不确定性与场景](references/zh-CN/uncertainty-and-scenarios.md#场景评估器)。它统计已给定的结果，不模拟过程、不替代真实概率校准。
- 可按任务使用 [决策简报](assets/zh-CN/decision-brief-template.md) 和 [科研假设记录](assets/zh-CN/research-hypothesis-template.md)，无需默认创建全部模板。

## 1. 明确研究问题与证据

从现有描述、公式、数据与代码整理：研究目标、决策变量、决策时点、参数/不确定量、数据来源、评价标准和资源预算。

明确谁在何时决定什么、此时已知什么、方案如何执行，以及何种结果算成功。实际目标与可计算代理指标分开；说明未建模的重要机制、用户给定的不可妥协条件及当前方案。没有这些语义时，求解器给出数字不代表问题已正确回答。

按任务建立决策简报和数据审查：粒度/时间窗/单位、主键与关联、缺失/重复、截断或删失、预测偏差、可识别性及字段在决策时是否可获得。数据不支持精细模型时选择可解释的简化，说明缺项和价值，而非编造参数。

用“研究假设—模型变化—可观测指标—验证实验”说明拟检验的主张。例如，新增鲁棒约束是否改善样本外违约率，以及为此增加多少成本。区分建模质量、求解质量和应用效果。

标注事实、用户约束、额外假设、待验证猜想。引用方法、定理或近期结论时核对原始论文或官方文档；提供可定位来源。禁止捏造引用、运行结果或创新性判断。

## 2. 建立可检查的数学模型

按照模型需要输出：
- 集合、索引、变量、参数及其维度、单位、取值域和数据来源。
- 原始目标方向、各目标项的意义及归一化方式。
- 每类约束的公式、实际含义、索引范围和边界情形。
- 假设表：假设依据、影响及拟验证方式。

必要时使用统一表达，但不强制改写用户模型：

\[
\operatorname{min/max}_{x}\ f(x;\theta),\qquad
g_i(x;\theta)\le0,\quad h_j(x;\theta)=0,\quad x\in\mathcal X.
\]

核查单位、索引、目标方向、定义域、边界、可行性和有界性。缺少存在性或唯一性条件时明确说明，不能由凸性直接推断。时间模型检查初末状态与递推；随机模型检查信息可用性和非预见性。

区分硬约束、软约束和偏好。对加权目标说明尺度与权重含义；用户要求优先级时考虑词典序或 ε-约束，而不是未经说明地用加权和替代。

对生产、排班、配送、预算、日程及科研资源配置，检查当前任务相关的批量/启动成本、最低需求、时间窗、切换、共享资源、角色资格、可达性和服务规则。领域模式仅用于发现遗漏，不默认替用户增加这些要求。约束要可追溯到需求或经标注的假设。

对重要或易遗漏的规则保留“来源—公式/代码—独立验证—反例”的链路；检验一个应被拒绝的方案，避免两个模块共同漏掉同一条规则。记录未映射或未验证的要求，不能以求解成功抵消它们。简单问题用短表即可，不强制登记系统。

## 3. 分类与模型重构

判断变量域、光滑性、凸性、可分性、稀疏性、二次/锥/逻辑结构及预期规模。为性质判断给出依据；工具的 DCP 检查失败不等同于数学上非凸。

对每项重构说明：原表达、变换表达、适用条件、等价/松弛/近似属性、解的恢复方法，以及原目标与新目标的关系。

特别检查 Big-M 的有效界、整数变量取整、分式变换的分母符号、乘积线性化、绝对值/最大值上图形式、惩罚与平滑。没有依据时不声称重构等价。

处理非凸、MINLP 或双层问题时明确局部/全局方法边界；用 KKT 替代内层问题前核查其适用条件和整体等价性。

## 4. 选择工具并实现

选型依据包括模型结构、规模、稀疏性、可用依赖、许可和所需保证。根据实际环境选择，例如：

| 模型 | 可考虑的入口 | 关键限制 |
| --- | --- | --- |
| LP / MILP | SciPy 的 HiGHS 接口或既有建模系统 | 保留状态、可行解、有效界及 gap |
| 排班/调度等离散逻辑模型 | OR-Tools CP-SAT 或既有 CP 系统 | 核对整数表达与缩放；feasible 不等于 optimal |
| 凸 QP / 锥规划 | CVXPY 与实际安装的兼容求解器 | 核对锥支持与数值精度 |
| 光滑非线性约束模型 | SciPy 或既有 NLP 系统 | 一般仅有局部保证 |
| 非凸混合整数模型 | 适配的 MINLP/全局求解器 | 区分局部求解、全局界和限时终止 |
| 特殊结构的大规模模型 | 分解、近端或领域算法 | 核查子问题与停止指标是否适用 |

不把建模库当作求解器；确认后端实际可用。需要最新功能时查询官方文档；记录实际运行版本，不在技能中固化版本承诺。

把数据加载、建模、求解和回验分开。保留原模型的独立目标/约束计算函数，避免仅使用求解器内部转换结果作验证。规模较大时优先稀疏表达，报告变量、约束和非零元数量。

配置暴露实例、模型参数、求解器、容差、随机种子、线程、时间/迭代限制和输出路径。提供实际可执行的入口与精确依赖记录；先在最小实例运行，再扩展。

解空间增长前估算变量/约束、内存和预算；枚举只用于适当的小规模实例或核查。大规模时依据结构考虑聚合、稀疏化、分解、启发式或早停，说明质量证据及其损失。超时已有可行解可在适用范围内使用，不以无限重试取代诊断。

## 5. 验证返回解与结论

求解后先检查返回解是否存在、维度/数值是否合法、原始状态及停止原因；没有可用解时不计算虚假目标或残差。

在原模型中重新计算目标、每类约束残差、边界与整数偏差，核对目标常数项、方向转换和变量恢复。保留绝对残差及尺度，说明容差与单位。

分别报告：求解器声称的状态、原模型回验结果、可用最优性证据。使用与问题匹配的梯度/近端/KKT残差或有效界；可行性通过不代表最优性通过。

对于非凸问题，驻点、多初值一致或更好的目标值均不自动认证全局最优。对于限时 MIP，可用整数解与未闭合的界仍具有信息价值，但不能标成已证明最优。

当用户需要实际执行方案时，再检查业务/物理过程：排程冲突、提前期、库存和共享资源、恢复/补救成本、方案转换与人员偏好等适用因素。仿真与历史回放能揭示已建模机制下的问题，不认证全部真实机制。返回可执行决策表、必要缓冲和有依据的替代方案，而非只给目标值。

最优性 gap 必须注明界的方向、来源、原目标映射及定义。没有有效界时标为未知；相对某个数值参考解的差值标为 reference difference。异常负 gap 应诊断，不静默截断或删除。

低精度状态、数值错误、不可行或无界结果按 [求解与认证](references/zh-CN/solver-validation.md) 诊断。改变约束、尺度、容差或求解器的每次重试留痕；先依据日志提出修正，不无限重复。硬约束不能未经授权软化。

区分方案对输入变化的可行范围、优化后的敏感性、决策变更幅度及实际失效。对运行方案记录模型/数据/业务语境版本、生效期、已锁定动作和需重新核查的事件。输入变化首先回验硬约束；是否值得重新求解再结合收益上界、切换成本与计算成本判断，不能用“变化很小”替代证据。

## 6. 实验设计与执行

完整实验先确定主指标、基线、实例生成/分割方式、规模、参数变化、重复次数、调参预算和资源预算。记录一个能在当前环境运行的起步配置，并说明其验证范围。

无预算时先做小规模冒烟验证；批量运行前估算总时间与内存。显式区分探索性结果和预先设定的比较，不根据已见结果挑选有利实例或停止规则。

选能回答研究问题的基线，如原模型、简单策略、松弛模型、成熟求解器或已有方法。跨模型比较时同时计算统一应用指标，不能只比较各自不同定义的目标值。

统一实例与资源口径，说明初始化、调参、预处理、编译、热启动和计时范围。随机实验尽量按实例/场景配对；确定性方法重复运行主要用于测量计时波动。

根据任务选择消融、单因素敏感性、参数交互、尺度扩展和样本外验证。涉及统计推断时说明独立实验单位、配对结构和不确定性来源；不把同一实例的重复计时当作独立样本。

怀疑实现错误时用有数学依据的变形检验：实体重命名、变量顺序置换、正比例单位变换、重复约束应保持相应解和目标；放宽约束不能降低已证明的最大化最优值。多重最优、限时求解和容差可能使具体决策或候选目标不单调，须检验适用不变量而非强行比较输出。

不确定性实验区分分布拟合/训练、调参、冻结方案后的评估及单列压力测试；不知道概率时不把任意场景权重称为真实分布。统一端到端成本与补救规则，同时比较平均表现、服务水平、尾部损失和硬约束违反。支撑不了泛化结论时保留为场景条件下的发现。

需要持续规划时区分提前决定与观察后补救，锁定已执行/已承诺决策。滚动求解更新实际状态，并按相同信息集与预测口径比较基线；不让历史回放使用当时未知的未来信息。

数据不足时优先找可能改变决策的未知量，提出可在决策前取得的最小测量或区分实验；有可信损失/观测模型才计算信息价值。信息增益、预测精度、决策收益是不同目标。没有可信概率时使用边界、反例与情景后悔比较，不伪造期望收益。

保存全部计划运行及原始记录，包含失败、超时和无解；区分正常的不可行场景与技术错误。失败不记为零成本或零 gap。汇总时报告有效样本数、失败数及分母。

## 7. 交付与完成标准

按当前任务交付必要文件，不机械生成空文件。完整实验通常包括：
- 模型说明与假设、数据来源及处理记录。
- 可运行代码、配置、实际环境信息及复现命令。
- 运行清单、原始记录、解/日志或其可追溯路径。
- 原模型回验、汇总表/图、研究结论及适用范围。

实际决策附上计划生效时点、输入快照、执行含义、相对当前方案的收益与切换代价，说明结论的失效条件。科研探索附上可证伪假设、最近基线、最小区分实验和下一项证据缺口；需要查新时记录检索范围，不由未搜到相似论文推断创新性。

用户未指定目录时遵循工作区约定，临时内容与交付物分开。报告中的数值必须可追溯到实际执行记录，合成与真实数据分开说明。

完整求解/实验任务完成前确认：小实例已运行且回验；指定实验已执行或明确说明环境阻碍；结论与状态、残差和界一致；复现入口可用。环境阻碍时交付已完成内容、精确缺项及待执行部分，不声称已完成运行。

最后先报告本次结论和证据，再给文件入口、复现命令及影响结论的限制。有限实验不证明普遍最优性、收敛性或创新性；不把样本内改善直接宣称为样本外收益。
